# Investigation and transfer lab

The preview can run fresh Meta investigations of the pinned compiled donor. Each run shows actual tool requests, hypotheses, observations and public conclusions. Loading the page does not call Meta. Conclusions retain `conclusionVerified: false`; completion checks evidence presence, not the correctness of an interpretation. The saved recovered component stays frozen.

All new investigation and Roadster generation trials share the persistent **$10 estimated generation ceiling** in ignored `reports/lab/`. Each investigation is capped at $0.50; legacy questions allow six generation requests and the new workflows have the bounded limits below. Roadster generation is capped at $0.05. The existing PAKU remix journal and $0.10 cap remain separate. One lab task runs at a time. Input-token preflight, saved reservations, returned usage and no automatic retries are required. Uncertain billing blocks further lab generation across restarts. Do not delete the journal to reset spending.

`POST /api/investigations` accepts `{questionId: "held" | "neutral" | "memory" | "extraction", idempotencyKey}`. `GET /api/investigations/<id>` returns real sequenced job progress and the public report. `GET /api/lab/status` returns availability and persistent accounting. POST requests require same-origin JSON, bounded input and a unique request key; repeating the same request reconnects to the same job.

The model receives the donor controls and its own tool observations, not original donor source, the recovered controller, saved conclusions or acceptance answers. A human supplies the registered target, tools and questions. Automated tests use explicitly injected fixtures and make no paid calls.

The host also supplies world-coordinate motion and timer observations through the existing human-mapped, hash-guarded donor registry. Meta chooses the inputs and interpretation; it did not discover the registry layout. The default neutral question deliberately tests a leftward history, which distinguishes preservation from a rightward default.

**View recorded investigation** loads `GET /api/investigations/saved/neutral-after-left` without inference. The hash-checked recording includes the actual model requests, experiments, complete donor observations and qualified conclusion. In that run Meta's preservation hypothesis was contradicted: after a left dash and full recharge, neutral moved right while left-held moved left. Why the donor chooses right remains outside that investigation's conclusion.

Both forms save the idempotency request before POST. If the response is lost, a deliberate reconnect reuses it; refreshing never starts a new paid request automatically. Jobs with known IDs resume polling. Roadster child lineage and full inherited intent are verified independently of natural-language interpretation.

The `memory` question uses persistent execution, code inspection and a controlled branch perturbation, with up to twelve generation requests / twenty-four tools inside the unchanged $0.50 cap. The `extraction` question allows sixteen / twenty-four and requires a newly submitted candidate to pass separate acceptance after freezing. The agent chooses code and experiments; no saved recovered implementation is supplied. Legacy questions retain their original limits.

Each investigation owns one isolated credential-free worker. Replay checkpoints reconstruct globals, linear memory and host storage; typed writes are restricted to experimental branches. PNGs and reconstruction journals persist in `sessions/<session-id>/`; accepted packages use `sessions/<session-id>/components/<candidate-id>/`. The UI exposes actual edits, comparisons, findings, captures and candidate feedback. See [the tool contracts, instrumentation coverage and finite scope](../docs/investigation-tools.md).

`memory` and `extraction` now offer `run_experiment` and a bounded JS/TS SDK in a separate WebAssembly interpreter. The host creates the paired branches and keeps full evidence outside the model context. Completed SDK operations are acknowledged only after persistence; interruption retains evidence without claiming interpreter-stack restoration. Both completion gates require a subsequent model turn linked to an actual experiment result, plus code inspection and a cited paired intervention.

These workflows use native client-executed `tool_search` and deferred focused namespaces. Hosted search is disabled because cumulative internal iterations do not fit the existing per-request reservation. Legacy questions retain flat tools. [Workbench contracts, security boundary, discovery and measured comparison](../docs/programmatic-experiments.md) explain the exact limits.

The extraction task now keeps function inspection and component-development tools directly available, while specialized tools remain deferred. After a completed recovery, the host runs separate JUJUMP and final-ZIP checks before publishing an independent project. `GET /api/investigations/<id>` includes the task's measured progress and artifact identity. Accepted donor recovery alone does not publish a recipient. The single fresh recovery attempt failed before inspection/candidate submission and is preserved as `recovery-handoff`; subsequent guidance/tool-profile changes have local validation only. [Recovery delivery and actual outcome](../docs/recovery-handoff.md) cover the interfaces, spending and limits.
